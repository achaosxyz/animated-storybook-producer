# 动态绘本制作人

[English](README.md) | 简体中文

一个在 Codex 中使用的技能，将原创或已有角色 IP 制作成动态绘本：从角色设计、脚本，到插画、配音、字幕与可观看的视频。

**不是单纯让图片动起来，而是编排整个画面。** 成片采用完整角色姿态、场景分层、镜头运动、声音和节奏组成的 2.5D 有限动画，不是完整三维动画，也不是拆开手脚临时拼装骨骼。

## 可以做什么

- 提出原创角色、伙伴关系和视觉参考，也可以直接使用你自己的 IP 创作。
- 编写脚本、设计分镜，制作完整角色姿态和场景素材。
- 使用豆包配音，制作双语字幕、按需原创配乐及 HyperFrames 视频合成。
- 交付包含 MP4、观看入口、检查证据和已知限制的待审包。

也可以只做脚本、分镜或某个制作阶段，不必一开始就制作完整视频。

## 在 Codex 中开始使用

将本地检出的技能源码或解压后的技能包安装到选定项目：

```bash
DISABLE_TELEMETRY=1 npx skills add /path/to/animated-storybook-producer --skill animated-storybook-producer --agent codex -y
```

源仓库：`git@github.com:achaosxyz/animated-storybook-producer.git`。将示例路径替换为实际技能目录，然后在自己的工作区中让 Codex 使用 `animated-storybook-producer`。

脚本和规划不需要图像生成能力或语音凭据。完整制作需要 Codex 图像生成能力、你自己的豆包语音 TTS API Key，以及 Node.js >=22、Python 3、FFmpeg/FFprobe 和 Chrome；ASR 凭据按需配置。运行依赖须显式安装，安装技能不会自动开通付费服务。具体配置见 [上手说明](references/getting-started.md)。

## 简要创作流程

1. **创建或导入 IP**：说明受众、角色关系、画风偏好并提供已有参考。新 IP 先选择角色方案，再确认角色设计和参考图。
2. **开始故事**：给出主题、语言、大致时长、横竖画幅和预期产物，先审阅脚本，再进入制作。
3. **确认分镜**：检查场景顺序、可见动作、节奏、素材需求和声音安排。
4. **制作待审版**：在已确认范围内，Codex 连续完成插画、配音、字幕、合成、按需配乐和检查；改变已批准的故事或角色设定时，回到受影响的确认节点。
5. **审核与保存**：查看实际视频和检查缺口，提出局部修改，再确认结果。归档保存和发布由你另行决定。

### 可以直接这样说

**先创建 IP：**

> 使用 animated-storybook-producer，为 3–6 岁儿童提出三个原创伙伴角色方案。画风活泼卡通，给出名字、关系特点和视觉方向。先只出方案，不生成图片。

**用已有 IP 开始创作：**

> 使用 animated-storybook-producer，读取 ./my-ip/ 下的设定和参考，制作一个约两分钟的横屏动态绘本，主题是两个伙伴探索雨天。先出脚本，等我确认后再做分镜。

**继续已有制作：**

> 继续 .build/my-story/ 中的动态绘本。先核对保存的状态和产物，从下一未完成阶段接着做，不重复生成已完成内容。

## 文件与确认由你掌握

IP、参考、审核记录和密钥保存在你自己的工作区，不放进技能安装目录。制作文件和待审包位于 `.build/<task-id>/`；剧集组织和长期归档由你的项目管理。技能不内置系列角色、作者账号或私有素材。

图像与语音服务可能产生费用，调用依据你的任务授权或可信常设授权执行。技术检查、视觉审核、实际试听和你的最终验收分别记录，未完成检查保持待审。技能不会自动批准、提交代码、上传或发布你的作品。

你可以用中文或指定的其他语言创作。Agent 指令和方法资源使用英文，README 提供内容对应的英文与简体中文两份。
